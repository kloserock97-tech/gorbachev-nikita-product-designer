# Прототип кейса на экранах из Figma — как у GRIF

Эталон — глава «Готовый интерфейс» кейса GRIF AI. Прототип любого кейса собирается так же и сверяется с ним
**скриншотом бок о бок**, а не счётчиками в DOM.

## Из чего сделан прототип GRIF (список для сверки)

1. **Экраны — из Figma один в один**, конвертером ниже. Никакой ручной вёрстки «по мотивам» и картинок с точкой.
   Сверка: рендер кадра в Figma (get_screenshot) против нашего экрана в Chrome, PSNR не ниже ~23 dB.
2. **Несколько сценариев вкладками** — `prototypes: [...]` в данных кейса, у каждого `tab`, `title`, `lead`,
   `live: "<папка>:<сценарий>"`, `device`. 2–3 сценария по 3–6 шагов: главный путь продукта и знакомство/вход.
3. **Шаги в данных = шаги сценария**, по порядку; у каждого шага `action` (что нажать), `why` (почему экран такой)
   и `image` — запасной кадр `public/cases/<кейс>/live2/s-<экран>.webp` (рендер нашего экрана, 1200 px).
4. **Кольцо-подсказка на настоящем слое**: `hint(s, s.find("<имя слоя из Figma>"), () => go(k + 1))`. Нажатие по
   этому слою ведёт дальше. Слой ищется по имени (`s.find`) или по тексту (`s.hot("Текст", up)`).
5. **Экраны живые** (stage.css): вход лесенкой (`g2-rise`, 30–60 мс), что в продукте грузится — крутится и
   дорастает (`g2-spin`, `g2-grow`), статусы с бликом (`g2-sheen`), новое выскакивает (`g2-pop`, `g2-drop`,
   `g2-dialog`), текст ответа — словами (`s.stream`), ввод — печатью (`s.type`), отмена — отсчётом (`s.countdown`).
   Свои имена слоёв кейса оживляются в `liven` модуля.
6. **Устройство**: веб — `device: "browser"`, кадры 1440; мобильный — `device: "phone"`, `design.w` = ширина кадра.
7. **Панель слева** (раскадровка, номер, «почему так») и **подсветка-шейдер** — движок, само.
8. «Меньше движения» — экраны сменяются без анимаций (движок).

## Модуль кейса

`src/ui/live/<папка>/flows.ts`:

```ts
import data from "./screens.json";
import { createRenderer, type Bundle } from "../grif2/render";
import { hint, make, type Flow } from "../grif2/kit";

const r = createRenderer(data as Bundle, "<ns>", (n, base) => `${base}cases/<кейс>/live2/${n}.png`);
const main: Flow = (s, ctx, step) => { const go = (k: number) => { ctx.go(k); main(s, ctx, k); }; /* … */ };
export const flows = { main: make({ w: 1440 }, main, r, (el, key) => { /* своё оживление */ }) };
```

Подключается сам (src/ui/live/index.ts → liveLoader), в данных кейса — `live: "<папка>:main"`.

## Конвейер Figma → screens.json

Правила Figma: сначала `create_session`; перед `use_figma` загрузить скилл figma:figma-use; файл не менять —
временная страница и sharedPluginData убираются шагом 5.

1. `use_figma` с кодом `1-store-converter.figma.js` — кладёт конвертер в sharedPluginData.
2. `use_figma` с кодом `2-export-bundle.figma.js`, где `IDS` заменён на id кадров. Возвращает id держателя
   (`holder`). Лимит возврата use_figma 48 КБ — поэтому данные идут в имена фреймов.
3. `get_metadata` по `holder` (ответ больше 75 тыс. знаков сохраняется в файл) →
   `node tools/f2h/3-decode.cjs <файл> <bundle.json>`.
4. `node tools/f2h/4-build.cjs <bundle.json> <кейс> <папка> '{"<id>":"<ключ>",…}'` → `src/ui/live/<папка>/screens.json`
   и картинки слоёв в `public/cases/<кейс>/live2/`.
4б. Картинки слоёв (фото, аватары): 4-build печатает, какие файлы нужны и с каких узлов. Для каждого — временный
   прямоугольник с теми же fills в натуральной пропорции на временной странице → `get_screenshot` → webp в
   `public/cases/<кейс>/live2/i-<хэш>.webp`, в рендере кейса `img: (n, base) => base + "cases/<кейс>/live2/" + n + ".webp"`.
5. `use_figma` с кодом `5-cleanup.figma.js`.

Шрифты: в макетах бывают шрифты, которых на сайте нет («Golos» → «Golos Text», «YS Text», SF Pro, иконки Font Awesome
Pro). 4-build дописывает запасной ряд; имена сводить к нашим (case-proto.css), глифы-иконки — заменять своими SVG.
Знак ₽ в подключённых Golos Text и Inter не входит в unicode-range — рисуется системным шрифтом.
Грабли: leading trim (CAP_HEIGHT) у подписей кнопок конвертер не переносит — текст садится на 3–4 px ниже; лечится
line-height по высоте слоя (пример — trimCaps в src/ui/live/agents2/flows.ts). Сценарий тестировать на своей сборке
(`vite build --outDir` + `vite preview`): общий dev-сервер перезагружает страницу, когда правят соседние файлы. У TEXT заливка — цвет букв (4-build убирает фон у текстовых классов); Vite dev не видит новые файлы
`public`, пока его не перезапустить; персонаж/картинка из прямоугольника может прийти с белым фоном — вырезать из
рендера кадра.
